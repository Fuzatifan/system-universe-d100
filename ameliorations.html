📄 Documentation & Gestion de version

Le projet manquait de documentation d'entrée et de configuration Git de base, rendant la prise en main difficile pour tout nouvel utilisateur.

Documentation 📖

README.md complet

Présentation de l'univers, du système d100, de la structure du dépôt, des instructions d'installation et de l'engagement accessibilité. La première impression du dépôt est désormais professionnelle et informative.

Git 🚫

.gitignore

Protection contre l'inclusion accidentelle de fichiers temporaires Python (__pycache__, *.pyc), d'environnements virtuels (venv/) et de fichiers d'éditeurs (.vscode/, .idea/).

Python 📦

requirements.txt

La dépendance pyttsx3 est maintenant documentée. L'installation se fait en une seule commande : pip install -r requirements.txt. Fini les messages d'erreur cryptiques au premier lancement.

🎨 CSS : Variables, Thème et Accessibilité

La feuille de style répétait les mêmes valeurs de couleur à plus de 30 endroits et ne proposait aucune adaptation à la préférence de l'utilisateur.

Avant

Problèmes identifiés

  • Couleur #9c27b0 répétée 30+ fois
  • Pas de variables CSS
  • Thème unique (sombre uniquement)
  • Pas de respect de prefers-color-scheme
  • Animations non désactivables
  • Pas de classe .sr-only
Après

Améliorations apportées

  • 40+ variables CSS (--color-*, --spacing-*)
  • Thème sombre et clair complets
  • Respect de prefers-color-scheme
  • Bouton de bascule avec sauvegarde localStorage
  • Respect de prefers-reduced-motion
  • Classe .sr-only pour l'accessibilité

⚙️ JavaScript : Modules et Nouvelles Fonctionnalités

Le script original était un seul fichier monolithique. Les fonctionnalités de test de compétence et de calcul de dégâts, présentes dans la version Python, étaient absentes du site web.

JavaScript 🧩

Architecture modulaire

Le code est désormais organisé en 6 modules distincts avec des responsabilités claires : Accessibilite, Theme, Navigation, LanceurDes, TestCompetence et CalculDegats.

Nouvelle fonctionnalité 🎯

Test de compétence web

Formulaire interactif permettant de saisir une valeur de compétence et un modificateur de difficulté. Le résultat (Réussite Critique, Réussite, Échec, Échec Critique) est annoncé visuellement et vocalement.

Nouvelle fonctionnalité ⚔️

Calcul de dégâts web

Sélection du type d'arme (Légère, Moyenne, Lourde, Très lourde) et calcul automatique des dégâts. Parité fonctionnelle complète avec la version Python du lanceur de dés.

Accessibilité 🔊

Annonces ARIA renforcées

Tous les résultats dynamiques (dés, tests, dégâts) sont annoncés via des régions aria-live="assertive" et lus par la synthèse vocale du navigateur. Les attributs aria-selected et aria-label ont été généralisés.

🐍 Python : Architecture OOP et Tests

Le script procédural a été entièrement refactorisé en classes orientées objet, avec une persistance de l'historique et une couverture de tests unitaires complète.

Avant (v1.0)

Architecture procédurale

  • Variables globales (engine, historique)
  • Historique perdu à chaque fermeture
  • Aucun test unitaire
  • Pas de séparation des responsabilités
  • Difficile à étendre ou à tester
Après (v2.0)

Architecture orientée objet

  • 4 classes : SyntheseVocale, Historique, MecaniqueD100, LanceurDes
  • Persistance JSON (~/.su_d100_historique.json)
  • 25 tests unitaires (pytest), tous passés
  • Méthodes statiques testables indépendamment
  • Prêt pour une interface graphique future

🎲 Game Design : Bible de l'Univers

L'univers "System Universe" était riche mais fragmenté entre plusieurs documents. Un document de référence central était indispensable pour la cohérence des futures créations.

Lore 🌍

L'Intégration documentée

L'événement fondateur du monde — "l'Intégration" — est maintenant décrit avec précision : date zéro, conséquences immédiates, apparition de l'interface du Statut et division en Zones de difficulté.

Personnages 👤

Arcs narratifs des PJ

Les 4 personnages pré-tirés ont désormais des arcs narratifs complets : passé, motivations, secrets et objectifs liés aux factions. Le Vétéran, l'Érudit, le Survivant et le Guérisseur sont de véritables personnages, pas seulement des feuilles de stats.

Économie 💰

Système économique

Introduction des Crédits Système (CS), de l'économie de troc de l'ancien monde et du système de loot/crafting (Cores de monstres, Blueprints). La campagne longue dispose maintenant d'une économie cohérente.

♿ Accessibilité : WCAG et Transcriptions

L'accessibilité était déjà une force du projet. Ces améliorations la formalisent et la complètent sur les points restants.

WCAG 2.1 📋

Déclaration d'accessibilité

Une page dédiée (accessibilite.html) liste l'état de conformité WCAG 2.1 pour chaque critère, les fonctionnalités implémentées et les limitations connues avec les solutions de contournement disponibles.

Audio 📝

Index des transcriptions

Toutes les dramatiques audio (MediEvil, Primal Hunter, Zazie, Battle Zone) ont leur script Markdown référencé dans un index centralisé, rendant le contenu audio accessible aux personnes sourdes et malentendantes.

Formulaires 🏷️

Labels et descriptions ARIA

Tous les champs de formulaire (test de compétence, calcul de dégâts) ont des labels explicites, des descriptions via aria-describedby et des messages d'erreur annoncés en temps réel.

Retrouvez l'ensemble du code source, des documents de jeu et des dramatiques audio sur le dépôt GitHub.
